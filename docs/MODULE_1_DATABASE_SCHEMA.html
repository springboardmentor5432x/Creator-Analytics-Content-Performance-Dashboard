CreatorIQ Database Architecture

Exact PostgreSQL relational schema implemented in Module 1 for User Management & Role-Based Profiles.

👤 users Primary Auth
  • PKuser_id
    INTEGER
  • name
    VARCHAR(100)
  • email
    VARCHAR(100) UNIQUE
  • password_hash
    VARCHAR(255)
  • role
    VARCHAR(50) [CHECK]
  • is_active
    BOOLEAN (default: true)
  • created_at
    TIMESTAMP
  • updated_at
    TIMESTAMP

  • PKcreator_id
    INTEGER
  • FKuser_id
    INTEGER UNIQUE
  • creator_name

    TEXT
  • profile_image
    VARCHAR(255)
  • website
    VARCHAR(255)

    VARCHAR(100)

  • updated_at
    TIMESTAMP

  • PKagency_id

  • FKuser_id

🔗 agency_creators Junction (M-to-N)
  • PKFKagency_id
    INTEGER (agencies)
  • PKFKcreator_id
    INTEGER (creators)
  • added_at
    TIMESTAMP
Allows an Agency to manage multiple Creators, and Creators to link with Agencies.

⚡ Relational Constraints & Integrity

users ➔ creators (1 : 1)
Foreign key with ON DELETE CASCADE. When a user with Creator role is removed, their profile is automatically removed.
users ➔ agencies (1 : 1)
Foreign key with ON DELETE CASCADE and UNIQUE constraint ensuring one agency profile per agency user account.
agencies ➔ creators (M : N)
Composite Primary Key on (agency_id, creator_id) preventing duplicate linkages between agency and creator.
CHECK (ck_users_role)
Database-level constraint strictly allowing only 'creator', 'agency', 'marketing_team', and 'admin'.
